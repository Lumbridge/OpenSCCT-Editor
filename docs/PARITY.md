# Feature parity

The feature checklist. Every feature of the stock ChaosTheory_Editor and of
[RE+](https://github.com/Lumbridge/SCCT_Versus_Reloaded_Editor) has a row, plus design, analysis and scripting features
neither has. Each row says where the feature lives in the new editor, whether it is built yet, and what it does better.

## How to read the tables

**From:** `stock` = ChaosTheory_Editor (UnrealEd 2 plus Ubisoft's additions). `RE+` = Reloaded Editor Plus (builds on
AllyPal's Reloaded Editor). `request` = asked for by map makers but in neither editor. `design` = a map design
guideline or tool outside the editors. `new` = not in any of them.

**Where:**

- `Core/<Folder>`: a module of the Godot-free `OpenScct.Editor.Core` library (see `ARCHITECTURE.md`).
- `ose <command>`: a command of the `ose` command line.
- `App: <name>`: a part of the Godot editor app: a panel, a tool, a menu or the viewports.

**Status:** what the code does today.

- `built`: it works.
- `partial: ...`: some of it works; the note says what is missing.
- `planned (M?)`: not started; the milestone in `ROADMAP.md` that brings it. M0 foundations, M1 interop, M2
  compiler, M3 editor shell, M4 geometry tools, M5 gameplay authoring, M6 lighting and render, M7 validation and
  play, M8 assets and sharing.
- `dropped` or `-`: not planned.

A planned row is a promise, not a claim that it works. The "Better than before" column describes the finished
feature.

Every edit in every row goes through one undoable command layer, and everything in Core is reachable from `ose` and
from scripts. So "undoable" and "scriptable" are not repeated in each row.
